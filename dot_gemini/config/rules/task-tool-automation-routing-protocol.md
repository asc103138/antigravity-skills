# 全域任務工具自動化三階路由與選用規範 (Task-Tool Automation Routing Protocol v1.0)

> **全域強制約束**：本規範適用於本機所有專案與對話環境。AI Agent 在接收任何任務時，必須自動依據本規範之「三階篩選機制」動態判定並選用最適工具與技能組合，嚴禁盲目隨機選用工具。

---

## 🎯 核心決策漏斗（三階篩選機制）

任何任務在動工執行前，必須依序通過以下三道篩選關卡：

```
                    ┌──────────────────────────────────────────────┐
                    │               使用者任務需求輸入               │
                    └──────────────────────┬───────────────────────┘
                                           │
                                           ▼
 🛑 第一階：必須標準  ┌──────────────────────────────────────────────┐
  (專案精細化首選)   │ 依產出品質與精準度分類，優先採用能產出最完美成果 │
                    │ 的工具（零跑版、高保真、結構完整、專業對標）。  │
                    └──────────────────────┬───────────────────────┘
                                           │ 符合精細化最高標準
                                           ▼
 ⚡ 第二階：初階標準  ┌──────────────────────────────────────────────┐
   (最小 Token 原則) │ 以最少 Token 消耗為原則：本機原生 CLI/MCP 優先，│
                    │ 數據本地管道直通，避免長文字與大檔塞入 Context。 │
                    └──────────────────────┬───────────────────────┘
                                           │ 確保 Token 最佳化
                                           ▼
 🎨 第三階：完美標準  ┌──────────────────────────────────────────────┐
   (美感增益疊加)    │ 疊加能提升視覺美感與專業質感的工具：高質感排版、 │
                    │ 雙欄對齊、AI 視覺素材、扁平化去背圖標、動態演示。│
                    └──────────────────────┬───────────────────────┘
                                           │
                                           ▼
                                 🚀 啟動最佳工具鏈執行
```

---

## 🛑 第一階：必須標準（專案精細化首選）

### 1. 核心準則
- **產出極致品質優先**：選擇能保證輸出「零損耗、不掉色、不跑版、原位對齊」的專業工具，不以粗糙簡化的替代工具應付。
- **專案領域嚴格對位**：
  - **PDF 結構與文件處理**：
    - 首選 **`PdfCraft` (Rust 原生 CLI / MCP)**：處理 PDF 頁面編排、高畫質轉圖、多檔合併分割、表單填寫、增量儲存、浮水印、壓縮最佳化。具備 Acrobat Pro 級保真度，絕不隨意使用容易損壞結構的簡易腳本。
    - 複雜表格微觀坐標提取：調用 **`pdfplumber`**。
    - 全格式多模態轉檔：一般文件首選 **`Docling`**（快速精準）；高密度 LaTeX 數學考卷與密集掃描首選 **`MinerU`**。
  - **國小教材與考卷命題**：
    - 強制遵循 **`g4-curriculum-review`** 三階審查規範（嚴禁超綱、版本用詞鎖定、精確字串比對）。
    - 產出 Word 考卷時，強制套用 **`antigravity-exam-win-converter`**（防跑版、雙欄排版、宋體/新細明體 Windows 相容）。
  - **行政數據與成績大表**：
    - 首選 **`pandas` + `openpyxl`** 向量化統計（五標、排名、自適應欄寬），100% 本機端隱私防線。
    - 教師排課配課：首選 **`teacher-course-assignment-skill`** 雙重會計檢查。

---

## ⚡ 第二階：初階標準（最小 Token 消耗原則）

### 1. 核心準則
- **本機直接運算直通 (Local Tool-First)**：
  - 優先透過終端 CLI（如 `pdfcraft-cli`）、本機 Python 腳本或專屬 MCP 工具在背景執行，產出直接寫入磁碟。
  - **嚴禁**將數十頁 PDF 原文、數千行原始 CSV/Excel 數據或大型二進位 Base64 塞進 LLM 對話 Context 中。
- **微量摘要回傳**：
  - 工具執行後，Context 僅接收「執行狀態、產出檔案路徑、精簡統計摘要（如頁數、平均分、檔案大小）」，避免 Context 膨脹。
- **精準參數過濾**：
  - 轉圖或抽取時，明確指定目標頁碼（如 `--page 1`），避免無意義的全書展開。

---

## 🎨 第三階：完美標準（美感增益疊加）

### 1. 核心準則
- 在通過第一階（功能品質）與第二階（Token 效率）後，主動疊加提升專案美感的工具與設計層次：
  - **簡報與投影片**：
    - 需生成互動簡報時：調用 **`html-slide-builder`**（加入 Reveal.js、AI 背景圖、滑桿視覺化演示）。
    - 需現代化演講投影片時：調用 **`antigravity-open-slide`**。
    - 需整套逐頁繪圖與視覺一致時：調用 **`teacher-slide-image-workshop`**。
  - **視覺素材與圖示**：
    - 調用 **`antigravity-draw`** 生成客製化風格插圖或扁平圖標，並配合 Pillow 裁切去背，取代生硬的 Emoji。
  - **版面與字型美學**：
    - macOS / 跨平台輸出自動匹配專屬字型（PingFang TC、Noto Sans TC、Biaodian 空格校正），維持適度留白，避免認知超載。

## 🧭 全域工具選用速查矩陣 (Routing Matrix)

| 任務需求類型 | 第一階：精細化首選 | 第二階：Token 省流手段 | 第三階：美感增益工具 |
|---|---|---|---|
| **PDF 合併/分割/旋轉/最佳化** | `PdfCraft` (CLI / MCP) | 本機背景原生處理，僅回報狀態與輸出路徑 | 內建高畫質渲染與向量外觀保持 |
| **PDF 轉圖/截圖預覽** | `PdfCraft` (`render --page N`) | 指定頁碼與必要 DPI，不全冊輸出 | 原生抗鋸齒與色彩設定檔保真 |
| **PDF 結構化抽取** | `Docling` / `pdfplumber` | 輸出 Markdown/JSON 本機存檔，僅回報摘要 | 結構化 Markdown 排版 |
| **考卷/學習單產出** | `g4-curriculum-review` | 提取本地課習關鍵詞比對，不讀全書入 Context | `antigravity-exam-win-converter` (Windows雙欄美學) |
| **段考大表統計** | `pandas` + `openpyxl` | 腳本直接處理萬筆數據，回傳五標摘要與 Excel 檔 | openpyxl 單元格色彩與斑馬紋排版 |
| **教學互動簡報** | `html-slide-builder` | 模組化 HTML 代碼直寫檔案 | `antigravity-draw` AI 背景 + 去背圖標 + 互動滑桿 |
| **班親會/家長日** | `parent-meeting-studio` | 結構化分步推進，分頁生成講稿 | 16:9 一致視覺簡報 + 響應式微網站 |
| **教師配課排課** | `teacher-course-assignment-skill` | 雙重會計校驗，僅輸出衝突名單 | 格式化領域確認版大表 |

## 🤝 RDQ 需求探索機制（四象限訪談）

> **強制觸發標準**：當使用者的任務需求符合以下任一情境時，**不得自行腦補、猜測或直接進行錯誤選用**，必須立即啟動 **`rdq`** 技能進行結構化訪談：

1. **資訊不對稱或邊界模糊**：任務描述僅有一兩句話，缺目標對象、使用場景、交付格式或排版需求。
2. **美感風格具多種分歧路徑**：例如簡報風格（童趣可愛風 vs 現代簡約風 vs 科技沉浸風）、考卷排版版型等需使用者抉擇。
3. **不可逆或高成本操作**：涉及大量重要檔案覆寫、對外公開發佈或大範圍架構重構。

### RDQ 執行規範（依四象限動詞鎖定）：
- **象限 Ⅰ（已明說的）**：**只擷取**——回顯確認使用者已說明的需求。
- **象限 Ⅱ（想問的）**：**只解答**——精確回答使用者的疑問。
- **象限 Ⅲ（知道卻沒說的）**：**只問**——當場答得出來的關鍵事實（例如：年級、學生人數、是否需要投影）。
- **象限 Ⅳ（沒想到的）**：**只陳述菜單**——將進階美感或優化選項端出來讓使用者勾選（例如：要不要加上學校浮水印？要不要產生 Windows 相容考卷？）。
- **預算控制**：預設 Lite 模式（1 輪 ≤3 題 ＋ 1 題菜單選項），確認需求規格卡後始得交棒執行。
