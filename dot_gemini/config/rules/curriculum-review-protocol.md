# 全域教材與試題生成三階審查規範 (Curriculum Review Protocol v2.0)

> **全域強制約束**：本規範適用於本機所有專案。未來任何專案中，凡涉及生成或修改**教材、考卷、學習單、教學簡報、作業評量或各類教學文件**時，**皆必須嚴格通過三階審查機制檢驗後始得輸出交付**。

---

## 🛑 第一階：最低門檻（Must-Have，紅線標準）

1. **先備經驗與年級對準**：
   - 必須嚴格符合目標年級學生的認知發展與先備知識，不得超綱引入高年級算則、過深生字或未學之概念。
2. **108 課綱代碼對齊**：
   - 必須明確標註並對齊 108 課綱學習表現代碼與學習內容代碼（如數學 `n-Ⅱ-7`、國語 `6-Ⅱ-1`、社會 `社2a-Ⅱ-1` 等）。
3. **教科書版本精確鎖定**：
   - 四年級固定鎖定：📘 數學（南一版）、📙 國語（翰林版）、📗 社會（康軒版）。嚴禁版本用詞混用。
   - 其他年級/科目亦須在生成前明確鎖定校內採用版本。
4. **跨 Agent 教科書版權重要規範**：
   - **嚴禁將出版社之課本、習作 PDF/Zip 檔案 commit 或 push 至公開 Git 儲存庫**（一律以 `.gitignore` 隔離）。
   - **執行審查前若偵測到本機工作目錄缺少課習教材，必須主動提示使用者**：「因版權限制，專案未附帶教科書原始檔案，請使用者先自行由校內合法教學資源庫下載所需版本的教科書/習作 PDF 放置於專案目錄後再行精確比對。」
5. **嚴禁幻覺審查（Anti-Hallucination Protocol）**：
   - 審查生字、詞彙、語法時，**嚴禁僅憑 AI 內建概略印象進行虛假審查**。必須實際讀取本機課習 PDF（或快取語料庫）進行精確字串比對（Exact Substring Match），確認生字詞彙是否確實出現在該冊課本/習作中。
6. **處置**：**未符合第一階門檻或含有超綱未學詞彙者，直接打回重置，禁止交付。**

---

## ⚠️ 第二階：中階目標（Should-Have，嚴格退回機制）

1. **認知負荷理論 (CLT)**：
   - 題幹與版面依據中年級學生工作記憶容量設計，核心思考元素控制在 3~4 塊之內，版面維持適度留白，避免認知超載。
2. **SDGs 永續發展目標融入**：
   - 生活化融入聯合國 SDGs 目標（如 SDG 12 責任消費、SDG 14 海洋生態、SDG 7 潔淨能源等）。
3. **STEAM 跨域探究思維**：
   - 結合生活科學觀察、工程設計動手做、數學生活應用或藝術美感設計。
4. **處置（嚴格退回修改）**：
   - 若生成內容缺少第二階要素，**嚴禁 AI 自行隨意捏造猜測**。
   - 必須明確列出待補強清單，經由教師確認同意後，始得修改補齊。

---

## 🌟 第三階：高階目標（Nice-to-Have，加分亮點）

1. **典型迷思概念誘答設計**：
   - 選擇題選項需針對學生常見迷思概念設計誘答，並在詳解中加註診斷標籤（例如分數分母連加 `M4-FRAC-01`、大數位值混淆 `M4-PLACE-01`、作文流水帳 `C4-TEXT-01`、一逗到底 `C4-PUNCT-01` 等）。
2. **海線在地生活化情境**：
   - 優先結合臺中港區、梧棲漁港、高美濕地、九降風、綠能風力、在地走讀踏查等真實生活經驗。
3. **18項議題融入與媒體素養**：
   - 適度融入海洋教育、環境教育、品德教育或媒體資訊辨識。
4. **處置**：**不勉強，達成時於報告中列為加分亮點。**

---

## 🔄 同型態輸入輸出原則與輸出標準

1. **格式對等交付 (Format Parity)**：
   - 輸入 Markdown (`.md`) 則輸出優化版 Markdown。
   - 輸入 HTML (`.html`) 則輸出優化版 HTML，並嵌入審查報告視圖面板。
   - 輸入考卷/Word (`.docx`) 則遵循 Windows 教務處雙欄排版與字型防跑版規範。
2. **集中輸出**：
   - 成果一律輸出至 `reviewed/` 專屬目錄，原檔案保持乾淨。
3. **必備審查報告**：
   - 交付教材時，文末或隨附必須包含標準化《AI 自我檢測審查報告 (Self-Review Report)》，清楚標明第一階、第二階與第三階檢測狀態。
