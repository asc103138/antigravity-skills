# Teacher Slide Image Workshop

用這個 Skill 把「想教什麼」轉成一套可直接使用的投影片圖片。全程以 AI image generation 產生 raster slide，不用程式碼繪圖、HTML/CSS、SVG、Canvas 或圖片合成來假裝成簡報。

## 1. 先完成素材引導

先檢查工作區與使用者已上傳的檔案，再用一組精簡問題補足必要資訊。若資訊已由檔案清楚提供，不要重複詢問。

必要輸入：

- 主題／教學想法，以及預計給誰看、希望看完能做什麼。
- 頁數；若沒有指定，依內容規模提出合理頁數並請使用者確認。
- 可用的簡報規格、PDF、PPTX、DOCX、文字大綱或既有投影片。
- 參考圖片的角色：`style/layout reference`、`character identity reference`、`content reference` 或 `edit target`。

建議但非必要：

- 固定主角圖、教師／學生角色圖、品牌圖像、色彩或字體規範。
- 最終資料夾名稱與輸出位置。
- 是否要保留每頁的精確繁中畫面文字，或只需要視覺主視覺。

若來源文件頁數與使用者要求的頁數不一致，必須明確指出差異並請使用者選擇範圍；不能默默截斷、合併或增加頁數。若使用者已明確要求「前 N 張」，照該範圍執行。

引導時可提供這個上傳清單：

1. 一份內容來源：PDF、PPTX、DOCX、文字大綱或主題想法。
2. 一至數張風格／排版參考圖。
3. 若要固定人物，再上傳主角 PNG/JPG；明確標示它是角色身份參考，不是整頁背景。
4. 若有現成品牌規範，再上傳色彩、字體、Logo 或版型說明。

提醒使用者：不要在提示詞或投影片中放學生姓名、病歷、聯絡方式或其他不必要的個資；若必須引用真實案例，先匿名化。

## 2. 完整閱讀與建立逐頁清單

先讀完整來源，不只看第一頁或檔名。

- PDF：先抽取文字，再把所有頁面轉成 PNG 供視覺檢查。使用 PDF skill 與可用的 Poppler／bundled workspace runtime。
- DOCX：抽取段落與表格文字，並用文件 skill 的 renderer 產生頁面 PNG；檢查設計說明中的色彩、字級、版型與角色規格。
- PPTX：先檢查每一張投影片與版型；若只把 PPTX 當參考，不要擅自改成可編輯 PowerPoint，除非使用者另有要求。
- 參考圖：需要當作本次生成輸入時，先用 `view_image` 視覺檢查；將其角色記錄在工作筆記中。

在暫存目錄建立 `slide-manifest.txt`，每頁至少記錄：

- 編號、標題、核心句、逐字畫面文字。
- 頁型：封面、章節、觀念、比較、流程、實作、檢核或收束。
- 配圖任務、角色出現位置、文字留白位置與主要色彩。
- 必須保留與禁止出現的元素。

每頁只保留一個核心訊息。內容多時先縮短句子或拆頁，不要把字縮到不可讀。

## 3. 鎖定視覺契約

在第一次生成前，從參考圖與設計說明整理一份短的視覺契約，並在所有提示詞中重複關鍵約束：

- 16:9 橫式；米白／霧灰或指定背景；柔和漸層與留白。
- 半透明白色圓角玻璃卡片、薄高光邊框、輕微陰影；保持乾淨層次。
- 主要文字使用深藍；以一個輔色與一個提醒色支撐流程、練習或警示。
- 教師是主角，AI 是協作助教，不要把 AI 畫成主導教學的機器人。
- 若有角色身份參考，固定髮型、臉型、服裝、描邊、質感與配色；只改姿勢、表情、道具與場景。
- 參考圖片只用來控制風格／版型／身份；不要無意間複製參考圖上的文字或內容。

把逐頁提示詞記錄在暫存的 `prompt-record.txt`。提示詞格式可參考 [references/prompt-schema.md](references/prompt-schema.md)。

## 4. 逐張使用 AI 生圖

使用內建 `image_gen` 工具，採一張投影片一個生成呼叫：

1. 先生成封面或一張代表頁，確認角色身份、文字可讀性、構圖與色彩；必要時先修正視覺契約。
2. 每張投影片獨立生成，不用 `n` 取代不同頁面，也不要把多張投影片塞進同一張圖。
3. 每次提示詞都明確指定 `Asset type: standalone 16:9 slide image`、頁面核心任務、構圖、文字留白與 exact text。
4. 需要固定角色時，先完成 `view_image`，再以 `referenced_image_paths` 傳入角色身份參考；在提示詞寫清楚「保留身份特徵，變化姿勢／道具／場景」。
5. 需要風格參考但不是編輯目標時，將圖片描述成 style/layout reference，不要把整張參考圖當成需要逐像素複製的 edit target。
6. 畫面文字要逐字放入提示詞，要求繁體中文、正確標點、不要 filler text、不要 pseudo-glyphs、不要 watermark。若生成文字錯誤，重新生成該頁或做一次針對性的 image edit；不要用程式碼後製文字。
7. 每次生成後，從工具回傳的 `$CODEX_HOME/generated_images/...` 路徑把成品複製到使用者指定的輸出資料夾，檔名使用 `01.png`、`02.png` 等零填充編號。不要只把檔案留在預設生成目錄。

若 image generation 工具不可用，清楚告知無法完成 AI 生圖；不要悄悄改用 PIL、SVG、HTML、Canvas 或其他程式化繪圖替代。

## 5. 交付前 QA

生成完成後，先用 [scripts/validate_slide_images.py](scripts/validate_slide_images.py) 檢查：

- 數量與編號是否與要求完全一致。
- 每張是否為可讀取的 PNG、16:9、尺寸一致。
- 是否有缺檔、重複檔名或多出未要求的投影片。

再進行視覺 QA：

- 用 contact sheet 看整套節奏、配色、角色一致性與頁型變化；contact sheet 只供檢查，不是交付成品。
- 至少逐張檢查封面、章節／轉場、比較、流程、實作、檢核與最後一張的完整尺寸畫面。
- 檢查標題是否清楚、中文是否可讀、文字是否被截斷、人物是否被裁切、卡片是否互相重疊、背景是否搶過文字。
- 對有問題的頁面只做一次明確的針對性重生成，保留角色、色彩與版型契約，再重新檢查。

## 6. 輸出完整簡報資料夾

最終資料夾至少包含：

- `01.png` 至最後一張 PNG。
- `README.txt`：記錄頁數、尺寸、生成方式、參考圖角色、內容範圍與任何頁數差異。

除非使用者要求，不要把暫存提示詞、contact sheet、渲染中間檔或失敗版本放進最終資料夾。回覆時提供資料夾的絕對路徑與已完成的數量，並說明是否使用了角色身份參考圖。
